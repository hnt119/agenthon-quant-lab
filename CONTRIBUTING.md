# Contributing

Start with [setup](docs/user-guide.md) and [development](docs/development.md).
Keep changes scoped, preserve historical receipts and add a meaningful numerical,
accounting or contract regression when behavior changes. Run the affected tests,
then the full suite and generated-projection check. Describe actual checks and
remaining uncertainty in the PR.

For research entries, cite a canonical primary source, write an original summary,
distinguish paper findings from project evidence and preserve negative outcomes.
Do not add copyrighted PDFs, credentials, restricted data, grader/reference
material or raw private captures. Use independently authored fixtures.

Do not add live model calls, paid data, broker actions, generated-code execution
or broad strategy searches as incidental changes. These require explicit design,
budget and verification decisions. Do not tune examples to hide losing results.

# v0.3.1 Python distribution

This candidate adds a pip installation to the v0.3.0 source release and includes the later local report-clarification commit `aa7101f`. The wheel and sdist are the publication units. The CLI needs a writable directory for outputs and a Python environment that can install the declared NumPy and SciPy dependencies. The reference environment is CPython 3.12.7 on macOS arm64, NumPy 2.5.4 and SciPy 1.18.1. Parquet is an optional extra. The install and dashboard instructions target macOS and Linux. The BTC reproduction retains its recorded numerical tolerances on other supported environments.

## Run from the local wheel

Create and activate an empty Python 3.12 environment, then install the wheel by its absolute path. From any writable directory, run `quant-lab doctor`, followed by `quant-lab btc-study`. The resulting Markdown report, static HTML dashboard and eight artifact comparisons are under the new output directory printed by the command. The source-based Codex integration continues to use a checkout and its own environment. [Existing skill setup](../plugin-guide.md)

| CLI path | Installed input and output behavior |
|---|---|
| `--version`, `doctor` | Identify the version, installation mode, local resources, dependencies and optional skill. Wheel runs record a null Git revision. |
| `btc-study` | Load the protocol, snapshot, attribution, original receipt and eight saved outputs from the installed package. Verify both source inventories and reconstruct into a fresh folder. |
| `example options/trading/historical` | Load the three bundled specifications, synthetic CSV or Q2 Bitstamp CSV. Resolve example data alongside its specification. |
| `archive papers/experiments` | Search bundled, curated public JSON. Historical paths and experiment IDs are citations. |
| `run`, `inspect-data` | Read the user’s local specification and its relative data path. |
| `reproduce`, `explain`, `verify-inputs`, `bundle` | Use a user-selected run folder. Generic reproduction requires matching source fingerprints. Bundles carry private inputs and provenance. |

The original protocol and receipts keep their v0.3.0 identities. The [compatibility record](../../packaging/btc-compatibility.json) binds the original source map and the exact ported map, including the new resource loader. An unknown source map fails verification. Each fresh BTC receipt identifies the compatibility record. Compare its eight output hashes, followed where applicable by the original structured numerical comparison. The chart still requires byte identity. [Study report](../../reports/btc-financial-v1/README.md) · [Data notices](../../DATA-NOTICES.md)

## Qualification and publication

1. Review this branch, its [artifact qualification script](../../scripts/check_distribution.py), and the installed CLI test. Build the wheel and sdist from the same qualified commit with `python -m build --sdist --wheel`; validate with `python -m twine check --strict dist/*`. Rebuild a wheel from the sdist with `python -m pip wheel --no-deps --no-cache-dir -w rebuilt dist/*.tar.gz` and run `python scripts/check_distribution.py dist/*.whl dist/*.tar.gz rebuilt/*.whl`. In a clean wheel environment, run `python -I scripts/check_installed.py /absolute/new/directory`. Add `--exact` to require byte identity in the recorded environment.
2. Before publication, the PyPI account owner checks the project name again. For a new project, add a **pending GitHub publisher** for project `agenthon-quant-lab`, owner `hnt119`, repository `agenthon-quant-lab`, workflow filename `pypi.yml`, GitHub environment `pypi`. If the name already belongs to this owner, add the publisher under that project's settings. An index 404 does not reserve the name. Configure the matching GitHub environment with owner review and a release-tag deployment rule. [PyPI pending publisher instructions](https://docs.pypi.org/trusted-publishers/creating-a-project-through-oidc/)
3. After separate publication approval, push the branch and open the PR. Wait for source and distribution checks, integrate the approved tree, confirm the tag is unused and verify the integrated package inputs match the qualified source. If package inputs changed, build, qualify and approve the replacement files first.
4. Tag the qualified integrated commit `v0.3.1`. Attach the **approved local wheel and sdist** to that GitHub release. Re-read both SHA-256 values. Dispatch `pypi.yml` on the **tag** with those two digests. The read-only qualification job verifies both assets, the release version, source contents, wheel rebuilt from the sdist, and a fresh Linux replay. The protected publishing job receives exactly these files and uses PyPI OIDC. PR checks cannot publish. No account API token is required.
5. Verify the two SHA-256 values on PyPI and repeat the clean installation from the public index. Preserve any failure and its receipts. Published files on PyPI cannot be replaced in place.

# Development guide

Use `python3 scripts/setup.py` from a source checkout. The package has no network
runtime path for financial calculations. New capabilities should have one narrow
specification, explicit units, deterministic calculations and independently
justified checks before adding UI or model assistance.

The shared APIs are `agenthon_quant.options.run(spec)`,
`agenthon_quant.trading.run(spec, data_path)` and `records.execute(spec_path, out)`.
The first two return results/checks/assumptions; the last owns snapshots, versioning,
publication and reports. CLI and skill stay thin. `archive.py` searches the curated
JSON; `onboarding.py` owns diagnostics, skill links and private bundles.

Run affected tests first, then `python -m unittest discover -s tests -v`.
`python scripts/verify_release.py --out runs/check-NEW` exercises examples,
reproduction, explanation and deliberate corruption via the real skill helper.
Never rewrite a historical run to make it pass a new source fingerprint.

## Archive and website projection

Edit `research/papers.json` and `experiments/experiments.json`, preserving stable
IDs and source provenance. Use original short summaries and canonical links, not
paper PDFs. Add complete unknown/status labels, unsuccessful outcomes and source
hashes. Then run:

```sh
.venv/bin/python scripts/export_site.py
.venv/bin/python scripts/export_site.py --check
.venv/bin/python scripts/export_site.py --check --site-root /path/to/portfolio
```

`site-export/` is generated. The exporter allowlists fields, checks categories and
cross-links, and rejects local paths and credential-like payloads. Human publication
review is still required. Its pricing corpus is generated by the Python engine;
the portfolio's Node tests compare its browser calculator to those values with
an explicit approximation tolerance. Do not manually maintain a second archive.

The portfolio owns its static React UI and review/merge process. This repository
owns Python, the skill, canonical evidence and release qualification. No homepage
or hosting change follows from a toolkit release.

## Release discipline

Keep the original source and tags immutable. Freeze source first, run qualification,
and commit evidence separately. Record hashes of source, archive/projection and
reports. Audit newly reachable Git history before publishing. An annotated tag is
a version label; do not call it a signed release unless it was actually signed.
The historical root `release-manifest.json` describes v0.1; newer receipts live
under `docs/releases/`.
